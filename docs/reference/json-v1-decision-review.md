## Schema constraints and deliberate limits

Final result fields and module shapes are bound to each operation. `check` has
only Slackware; dry-run/apply each have six different module objects. Check raw0
reports success/no updates, raw100 success/updates, other integers failed/null.
Final result codes0/1 belong to check/dry-run and0/2/3/4/5 to apply. Exact schema
conditionals bind success/partial/boot_safe/reboot and exit_code_meaning. Empty
warnings/errors arrays are data; the schema does not prove every reported
module state or list/count relationship is true of the host.

Booleans never stand in for numeric codes. JSON Schema integers permit integral
numeric spelling such as1.0. Original v0 strict Python decoded-type expectations
stay unchanged and are not silently made the prospective wire-number grammar.
Nullable statuses mean not-run/unavailable in their current field scope; they
are not coerced to0. Event raw codes and raw check integers have different domains
from nonnegative action statuses and final stable codes.

Timestamps deliberately permit empty and non-date strings. Paths are reported
text, not canonicalized trusted resources. Open diagnostics and selected states
may change text; closed enums and English stable exit-code meanings may not
change silently. Array order/duplicates remain significant. Queue/option strings
must not be executed. Generic counter/list equality is not a schema promise;
case-specific native consumers may require additional relationships.

The complete profile is strict UTF-8 NDJSON, nonempty frames and final LF; CRLF
is allowed. Duplicate keys, non-JSON constants, mixed operation/version, sequence
gaps, duplicate starts or missing final completion fail the relevant profile.
A complete stream starts at1. The explicit fragment profile permits a positive
offset but still needs one initial start and one final completion; it does not
accept an arbitrary middle segment. Neither profile proves action pairing,
lossless transport, durable recording, trusted clocks, drain or terminal custody.

Final events map0/4/5 to success,2 to warning,1/3/6/7/8 to failed. Supplied6/7/8
records do not prove those early exits emit any real lifecycle. Help, argument,
configuration, privilege, lock and setup failures may have no JSON/NDJSON.
Consumers retain the process status and stderr independently; absence is never
replaced by a fabricated result. A partial stream is still incomplete.
